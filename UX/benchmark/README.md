# KRDS 적용 사이트 벤치마크 (캡처일 2026-10-30)

- 모든 캡처는 로그인 없이 보이는 공개 화면이며 상태를 바꾼 동작은 없다. 파일명은 `유형_사이트_폭.png`.
- 폭 1920과 360은 브라우저 뷰포트 폭(CSS px)이다. PNG는 2배 해상도(3840 / 720px)이고 첫 화면 한 장(스크롤 없음)만 담았다.
- 정부24 첫 화면에는 만족도 조사 팝업이 떠 있어 닫기를 눌러 닫은 뒤 캡처했다.
- 아래 "눈여겨볼 점"의 따옴표 문구는 모두 해당 화면의 실제 텍스트이다. 간격·위계·배치 서술은 캡처 이미지를 보고 적었고 px 수치는 재지 않았다.

## 3. 확인하지 못한 것

- 단계 표시기를 쓰는 민원 신청서(로그인 필요)와 입력창 인라인 오류 화면: 공개 화면으로는 못 봄. 회원가입 1단계로 대체했고 입력 오류는 모달 방식만 확인.
- 정부24 상세 정보의 360 폭 모바일 배치는 캡처했으나 별도 분석은 하지 않음.
- 각 사이트가 KRDS 컴포넌트를 "정확히" 따르는지(토큰 값, 간격 px)는 재지 않았다. 확인한 것은 공식 배너 문구와 화면 구성 일치 여부까지이다.
- KRDS 사이트 404, 정부24 404에 공식 배너가 없는 것은 화면에서 본 사실이다. 의도 여부는 모름.
- 복지로, 온통청년 등 KRDS 사례 목록의 다른 사이트는 열어 보지 않았다.

## 4. 우리 화면에 적용할 점

1. 화면 위쪽 순서를 배너, 로고와 유틸리티, 주 메뉴, 본문 제목으로 고정한다. (검색첫화면_정부24_1920.png, FAQ_정부24_1920.png)
2. 검색창을 첫 화면 본문 맨 위에 두고 placeholder는 질문형 한 문장으로 쓴다. 예: 정부24 "안녕하세요. 무엇을 알고 싶으세요?" (검색첫화면_정부24_1920.png)
3. 검색 결과는 필터 영역에 항목별 건수를 병기하고 결과 건수를 제목 줄에 크게 둔다. 정렬 선택지 이름은 짧은 명사로 쓴다. (검색결과필터_정부24_1920.png, FAQ_정부24_1920.png)
4. 빈 결과는 "검색어 OOO에 대한 검색 결과가 없습니다."에 이어 해결 방법을 2~3줄로 준다. (빈검색결과_KRDS_1920.png)
5. 404는 아이콘, 한 줄 제목, 원인 설명, 버튼 하나(메인으로 가기)만 가운데에 둔다. 우리 화면은 공식 배너와 머리말을 유지할지 별도로 결정한다. (오류404_정부24_1920.png, 오류404_정부24_360.png)
6. 단계 표시기는 점 3개와 단계 이름 아래에 "1단계 / 3단계"와 현재 단계 제목을 한 번 더 둔다. 360에서는 이름을 줄이고 제목으로 대신한다. (단계신청_정부24_1920.png, 단계신청_정부24_360.png)
7. 필수 표시는 "(필수)" 글자로, 선택은 "(선택)" 글자로 쓰고 색에만 기대지 않는다. 하단 버튼은 "취소하기"와 "동의하기"처럼 동사형으로 쓴다. (단계신청_정부24_1920.png)
8. 오류 문구는 "무엇을 해 달라"로 끝낸다. 예: "정부24 이용 약관(필수)에 동의해 주세요." 인라인 오류 형태는 KRDS 컴포넌트 문서에서 따로 확인해야 한다. (입력오류_정부24_360.png)
9. 목록(공지, FAQ)은 360에서 표 대신 제목 2줄 + 날짜 한 줄 카드로 바꾸고 검색 버튼은 전체 폭으로 한다. 고정 공지는 핀 아이콘, 새 글은 라벨로 구분한다. (공지목록_정부24_360.png, FAQ_KRDS_360.png)
10. 로그인 화면은 방식별로 제목 + 한 줄 설명 행을 쌓고 회원가입 안내는 맨 아래에 둔다. 우리 서비스에 맞는 인증 방식 수만 남긴다. (로그인_정부24_1920.png, 로그인_정부24_360.png)
