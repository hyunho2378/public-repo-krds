# 퍼소나와 UX 원칙

- 문서 번호: UX-001
- 작성일: 2026. 10. 30.
- 상태: 초안
- 근거 자료: 2차 리서치 원자료 F_civil_servants.md(공무원 발언 12건, 통계), 공공 깃랩 역설계 recon.md(화면 26개, 불편 20개), GitHub와 실제 GitLab 역설계

## 0. 제품 정의 (2026. 10. 30. 사용자 확정, 모든 작업의 기준)
- 이 서비스는 정부 정보를 찾는 사이트가 아니다. GitLab과 GitHub 같은 코드와 개발 저장소 플랫폼이다
- 기본 사이트는 공공 깃랩(GitLab)과 GitHub의 모든 페이지와 기능을 그대로 가진다. 프로젝트 만들기, 업로드, 브랜치, 커밋, 코드 보기, 비교, 이슈, 머지 리퀘스트, 릴리스, 그룹, 검색, 탐색, 알림, 설정, CI/CD, 위키, 스니펫까지 원래 쓰던 화면과 흐름 그대로다
- 배치와 UX는 공공 깃랩과 GitHub를 합친 것이다. 디자인 시스템(부품, 색, 글자, 간격)만 KRDS다
- 그 위에 공공 깃랩 맥락 기능과 AI 기능을 더한다. 업무 문장 검색, AI 소개 카드, 분야 분류, 실행 환경 판정, 공개 준비 점검, 보안 파일 알림, 써 봤어요, 쉬운 의견, 법령과 기준 알림, MCP, 인수인계 문서, 운영 현황판 등
- 공무원 친화는 원래 기능을 빼거나 숨겨서가 아니라, 같은 화면에 쉬운 설명과 판단 정보를 덧붙여서 이룬다

## 1. 판단 기준
- 기준은 두 가지를 동시에 만족하는지다. 코딩을 모르는 공무원이 막힘 없이 쓰는지, 개발자가 GitLab과 GitHub처럼 코드와 저장소를 다루는지. 디자이너가 보기 좋은지는 기준이 아니다
- 화면 요소마다 "이 공무원이 이걸 보고 다음에 무엇을 하는가"로 남길지 정한다
- 답이 없는 요소는 뺀다. 개발자에게만 필요한 요소는 "개발자용 정보"로 접는다
- 값은 KRDS를 따른다. KRDS와 달라지면 결정 기록(D-번호)에 문제, 근거, 결정, 검증을 남긴다

## 2. 퍼소나

### 2.1 주 퍼소나 P1 찾아 쓰는 공무원
| 항목 | 내용 | 근거 |
|---|---|---|
| 업무 | 일반 행정. 문서 작성, 요약, 법령과 지침 대조, 반복 민원 답변 | 공노총 설문 기대효과 순서 |
| 개발 지식 | 없음. clone, 브랜치, 머지 리퀘스트, 터미널을 모른다 | AI 활용 교육 없음 59.4%(위성곤 의원실 설문) |
| AI 사용 | 범용 생성형 AI를 인터넷망에서 쓴다 | 인터넷망 사용 54.5% |
| 목표 | 내 업무에 쓸 수 있는 도구가 이미 있는지 확인하고 바로 써 본다 | "활용할 업무가 제한적" 1위(한국행정연구원) |
| 불안 | 써도 되는지, 문제가 생기면 누가 책임지는지 | 오류 시 책임 소재 불분명 49.8%(공노총) |
| 환경 | 업무 PC, 인터넷망과 업무망 분리. 프로그램 설치가 자유롭지 않다 | 행안부 2026. 7. 보도자료, 조달청 설명 |
| 막히는 곳 | 첫 화면이 로그인, 업무 말로 검색 안 됨, 파일 목록이 먼저 나옴, 실행 방법이 명령어뿐, 안내가 영어 | 불편 1, 3, 4, 5, 9, 10 |

### 2.2 보조 퍼소나 P2 만들어 올리는 공무원
| 항목 | 내용 | 근거 |
|---|---|---|
| 업무 | 현업 담당. 생성형 AI로 업무 도구를 직접 만든다 | 발언 1, 6, 9 |
| 개발 지식 | AI가 만든 코드를 쓰지만 코드 검증은 어렵다 | AI 결과물 검토 필요 96.9% |
| 목표 | 만든 도구를 다른 기관과 나눈다 | 공무원 B 씨 사례(행안부 2026. 7. 2.) |
| 불안 | 어디에 어떻게 올리는지 모름, 보안 파일이 같이 올라감 | B 씨 "어디에 어떻게 등록해야 하는지 알기 어려웠다", .env 공개 프로젝트 3개 |
| 막히는 곳 | 새 프로젝트 화면이 개발자 용어, 공개 전 점검 없음, 의견을 받을 길이 좁음 | 불편 2, 6, 10 |

### 2.3 주 퍼소나 P3 개발자 (P1과 같은 무게)
| 항목 | 내용 | 근거 |
|---|---|---|
| 업무 | 공무원 개발 담당, 협업 개발자, 서포터즈 개발 팀원 | 0x팀 구성, 공공 깃랩 실제 사용자 |
| 개발 지식 | GitLab과 GitHub를 매일 쓴다 | 공공 깃랩은 GitLab CE 그대로 설치됨 |
| 목표 | 코드를 빨리 읽고, 브랜치와 커밋, 머지 리퀘스트, 이슈를 원래 쓰던 방식 그대로 다룬다 | |
| 불안 | 쉬운 화면을 만들다 원래 기능이 사라지거나 숨거나, 코드가 안 보이는 것 | 사용자 지시 2026. 10. 30. |
| 기대 | 단축키(/, t, f), 줄 링크, Blame, diff 나란히 보기, 클론 주소 복사가 원래 자리에 있음 | 직접 사용 기록 UX/handson |

### 2.4 두 퍼소나를 한 화면에서
- 기본은 GitLab, GitHub와 같은 화면과 기능이다(P3가 낯설지 않게)
- P1을 위한 것은 같은 화면에 덧붙인다: 쉬운 설명(용어 옆 보조 문구, 툴팁), 판단 정보(오른쪽 정보 영역), 다음 행동 안내, AI 기능
- 덧붙인 것이 코드를 가리지 않는다: 코드 보기, diff, 파일 트리 영역에는 덧붙임을 넣지 않고 주변(머리, 오른쪽, 빈 상태)에 둔다
- 코드 가독성 기준: 고정폭 글꼴, 구문 강조(D-05, 대비 4.5:1 이상), 줄 번호, 줄 높이 일정, 가로 스크롤(줄바꿈 선택 가능), 긴 파일 성능
- 운영 기관(행안부, 기관 정보화 담당)은 운영 현황판(P-23)에서 다룬다

## 3. UX 원칙

| 번호 | 원칙 | 화면에서 하는 일 | 근거 |
|---|---|---|---|
| U1 | 업무 말로 찾는다 | 첫 화면 가운데 검색. "출장비 정산"처럼 문장으로 입력. 분야, 기관, 실행 환경 필터 | 불편 3, F-01~F-03 |
| U2 | 하는 일을 먼저 보여 준다 | 프로젝트 첫 화면은 소개 카드(하는 일, 대상 업무, 실행 환경, 기준 날짜). 파일 목록은 탭 뒤로 | 불편 9, F-11 |
| U3 | 판단 정보는 한곳에 모은다 | 실행 환경(인터넷망, 업무망, 설치 필요 여부), 써 본 기관, 이용 조건, 갱신일을 오른쪽 정보 영역에 고정 | 불편 1, 7. GitHub About 영역 |
| U4 | 개발 용어는 원래 이름 그대로 두고 쉬운 설명을 덧붙인다 | GitLab, GitHub 메뉴와 기능은 그대로 보인다. "브랜치", "머지 리퀘스트", "CI/CD" 옆에 쉬운 설명(툴팁, 보조 문구). 기능을 접거나 숨기지 않는다(0장) | 불편 10, 16 |
| U5 | 로그인 없이 둘러본다 | 첫 화면은 둘러보기. 로그인은 의견 쓰기, 써 봤어요, 올리기 때만 요청하고 이유를 함께 보여 줌 | 불편 2, 5 |
| U6 | 막히면 이유와 다음 행동을 준다 | 없는 주소, 권한 없음, 점검은 각각 다른 오류 화면. 빈 목록에는 다음 행동 버튼 | 불편 4, 15, 19 |
| U7 | 불안을 줄이는 신호를 보여 준다 | 공개 준비 점검 결과, 기준 날짜, 써 본 기관 수. 보안 파일은 비공개로 제작자에게만 알림 | 책임 소재 49.8%, F-21 F-22 |
| U8 | 한국어와 쉬운 행정 용어만 쓴다 | 영어 안내문 0. KRDS 문구 지침 | 불편 4, 8 |
| U9 | 만든 사람을 밝힌다 | 공공 깃랩 프로젝트는 공무원 개인이 만든다. GitLab, GitHub처럼 만든 사람(공개 프로필 이름)과 소속 기관을 함께 보여 준다. 예: "마포구청 공혁준 / HWP_AutoDocFit". 이름은 프로필 링크로 이어진다. 연락처, 이메일 같은 비공개 정보는 쓰지 않는다 | 사용자 지시 2026. 10. 30.(누가 만들었는지 알려야 한다), 공공 깃랩 공개 프로필 |
| U10 | 오래 보는 화면을 고려한다 | 밝은 화면, 어두운 화면(D-01), 선명한 화면 모드 3가지. 시스템 설정 따르기가 기본 | D-01 |

## 4. GitHub, GitLab에서 가져오는 것과 버리는 것

| 구분 | 가져옴 | 이유 | 버림 또는 접음 | 이유 |
|---|---|---|---|---|
| 프로젝트 머리 | 이름, 한 줄 설명, 주제 칩, 관심 표시 | 판단 첫 단서 | 포크 수, 브랜치 선택 | P1에게 의미 없음 |
| 오른쪽 정보 영역 | GitHub About 영역 구조 | U3 판단 정보 고정 위치 | 언어 비율 막대 | 판단에 쓰이지 않음 |
| 탭 줄 | GitHub 저장소 탭 줄(소개, 파일, 변경 기록, 의견) | 익숙한 구조, 화면 이동 단순 | Actions, Projects, Wiki, Security 탭 | 비어 있거나 개발자 전용 |
| 검색 결과 | GitHub 검색 왼쪽 필터 묶음 | 조건 거르기 | 코드 검색, 정규식 | 개발자 전용 |
| 의견 | GitHub 이슈 양식 선택(오류 신고, 기능 요청, 도입 문의) | 무엇을 쓸지 안내 | 라벨, 마일스톤, 담당자 지정 | 제작자 쪽 기능 |
| 가져오기 | GitLab 코드 메뉴 위치 | 익숙한 자리 | SSH, HTTPS 주소만 있는 메뉴 | "실행 안내"로 바꿈(U3) |
| 왼쪽 탐색 | GitLab 왼쪽 메뉴 | 화면이 넓을 때 이동 | 빈 메뉴(스니펫, CI/CD, AI 카탈로그) | 불편 14 |

## 5. 확인 필요
- 퍼소나 근거 중 공무원 직접 발언은 12건이다. 공무원 인터뷰(인터뷰 패키지 준비됨)로 보강이 필요하다
- 업무 PC에서 실행 가능 여부의 판정 기준(설치 필요, 관리자 권한, 망 구분)은 행안부 지침 제정 전이다
