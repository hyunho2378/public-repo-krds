## 1. 기준
- 저장소 안 모든 화면은 하나의 틀 안에서 움직인다. 머리, 탭 줄, 브랜치 선택, 경로가 화면마다 같은 자리에 있다(D-04)
- 공무원이 보는 판단 정보와 개발자가 보는 코드 화면이 같은 틀 안에서 탭으로 이어진다. 화면을 따로 만들지 않는다
- 코드 저장소라는 점을 살린다. 정부 사이트의 글 나열식 구성을 쓰지 않고, GitHub와 GitLab에서 검증된 파일 표, 코드 보기, 변경 비교 구성을 따른다
- 값과 부품은 KRDS를 따른다. KRDS에 없는 코드 표시 요소(고정폭 글자, 구문 강조, 변경 비교 색)는 D-05에서 KRDS 색 토큰으로만 정한다

## 2. GitHub와 GitLab 패턴에서 우리 화면으로

## 3. 저장소 공통 틀 구성(위에서 아래)
1. KRDS 헤더(공식 배너, 서비스명, 메인 메뉴)
2. 브레드크럼: 도구 찾기 > 기관 > 도구 이름
3. 프로젝트 머리: 도구 이름(제목), 공개 배지, 한 줄 설명, 기관 / 갱신일, 오른쪽 버튼(써 봤어요, 관심 표시)
4. 탭 줄(KRDS 탭): 소개, 사용 방법, 코드, 변경 기록, 의견. 각 탭 옆에 건수(의견 3 등)
5. 본문 2열(PC 1440 이상): 왼쪽 탭 내용, 오른쪽 정보 영역 고정. 1024 이하 1열, 정보 영역은 탭 내용 위(소개 탭) 또는 아래(그 밖)
6. 코드 탭 안 하위 줄: 브랜치 선택, 경로(브레드크럼), 파일 찾기, 내려받기, 하위 메뉴(파일, 변경 제안, 브랜치와 태그, 릴리스, 참여자)

## 4. 상태
| 화면 | 상태 |
|---|---|
| 코드 둘러보기 | 불러오는 중(표 자리 스켈레톤), 빈 저장소(파일 올리기 안내), 권한 없음, 불러오기 실패(다시 시도) |
| 파일 보기 | 일반, 큰 파일(앞 1,000줄과 원본 보기 안내), 이진 파일(내려받기만), 이미지(미리 보기), 마크다운(렌더와 원문 전환) |
| 변경 비교 | 통합, 나란히, 변경 없음, 큰 변경(파일별 접힘) |
| 목록(커밋, 이슈, 머지 리퀘스트, 릴리스) | Ideal, Empty(다음 행동), Loading, Error |

## 5. 폭
- 1920, 1440: 2열, 코드 보기 최대 폭은 콘텐츠 폭 전체
- 1024: 1열, 정보 영역은 접힘 묶음
- 768: 1열, 탭 줄 가로 스크롤
- 360: 탭 줄 가로 스크롤, 파일 표는 이름과 날짜만, 코드 보기는 가로 스크롤과 줄 바꿈 전환, 변경 비교는 통합 보기만
