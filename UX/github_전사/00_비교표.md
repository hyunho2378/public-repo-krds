# GitHub 대비 비교표 (1차)

- 작성일: 2026. 10. 30.
- 범위: 1차로 실제 측정·확인한 화면만(저장소 홈, 파일 보기). 나머지 화면은 구조상 추정이며 "미확인"으로 표시
- 우선순위: 눈에 띄는 차이 순(밀도 > 구조 > 문구)

## A. 공무원 덧붙임을 뺐을 때도 남는 기본 차이
(= 우리 서비스가 GitHub 기반을 표방하면서 GitHub와 다른, 덧붙임이 아닌 순수 기본기 차이. UX/07 0장 "기본은 GitHub, 덧붙임은 위에" 원칙 위반 항목)

| 번호 | 항목 | GitHub | 우리 | 문제 |
|---|---|---|---|---|
| A1 | 파일 표 행 높이 | 40px | 51px | 기본 밀도가 GitHub보다 낮음(덧붙임과 무관) |
| A2 | 파일 이름 글자 크기 | 14px | 17px | 동일 |
| A3 | 탭 줄 글자 굵기 | 400(보통) | 700(굵게) | 시각적으로 무겁고 GitHub 느낌이 아님 |
| A4 | 사이드바 메뉴 버튼 크기 | (GitHub엔 저장소 왼쪽 사이드바 자체가 없음. 공공 깃랩 구조를 썼으므로 공공 깃랩과 비교해야 함) | 38px/17px/700 | 공공 깃랩 실측과 비교 필요(2차 작업) |
| A5 | 어두운 화면 기본값 | GitHub는 로그인 사용자 설정을 따르되 신규/비로그인 방문자는 시스템 설정을 따름(다크 많이 씀) | 우리는 지금 밝은 화면이 기본 | UX/07 1장으로 수정 중 |
| A6 | 맨 위 "시제품입니다" 배너 | 없음(GitHub, GitLab 모두 운영 화면에 이런 배너 없음) | 모든 화면 상단 고정 | 이용자가 매 화면 보게 됨. UX/07 2장으로 삭제 중 |
| A7 | 코드 글자(monospace) | 12px/줄높이20px | 확인 필요(D2Coding 적용 크기) | 코드 갈래 조치 중 |
| A8 | README 위 안내문("제작자 설명에서 자동 정리했습니다") | 없음. 원문만 보여줌 | 있음 | 불필요한 메타 설명. UX/07 5장 "이 도구가 하는 일" 류 금지와 같은 맥락 |

## B. 우리 서비스 목적상 의도된 덧붙임(문제 아님, 확인용)
| 항목 | 내용 | 비고 |
|---|---|---|
| 업무로 찾기 | GitHub 전역 검색과 별개로 업무 문장 검색 | A-01, 유지 |
| 공개 준비 점검 | GitHub·GitLab에 이런 자동 점검 화면 없음 | A-03, 유지 |
| 써 봤어요 | GitHub Star와 다른, "실사용 기록"용 | 유지 |
| 실행 환경 배지 | GitHub에 없음 | 정보 영역에만 두고 목록에서 반복 금지(UX/07 4장) |
| 사이드바 쉬운 설명(작업 갈래, 코드 반영 요청 등) | 용어 옆 보조 풀이 | 유지, 단 목록 밀도를 해치지 않는 범위에서(현재 A4 문제와 얽혀 있음) |

## C. 미확인(2차 전사 필요, 구조 추정만)
커밋 상세, 비교, 브랜치/태그/릴리스, 이슈/PR 목록과 상세, Actions, Insights, 로그인, 검색, 탐색, 설정, 모바일 — `UX/handson/github`에 1차 캡처 95장이 있으나 측정값과 1:1 화면 전사는 아직 없음. 다음 작업자가 이어서 작성.

## 참고
- 이 표는 이번 교정 작업자가 직접 실측한 것만 "확인"으로 표시했다. 과거 작업자가 "완료"라고 보고했던 항목도 실제 배포 화면에서 재확인될 때까지는 신뢰하지 않는다(사용자가 지적한 패턴).
