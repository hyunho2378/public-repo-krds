# 01. 저장소 홈 (Repository home)

- 대상: github.com/microsoft/vscode (로그인 상태, 1440x900 측정)
- 우리 대응 화면: R-01 프로젝트 홈
- 캡처: shots/github_vscode_1440.png, shots/our_r01_1440.png

## 1. 영역 구조(위에서 아래, 왼쪽에서 오른쪽)
1. 전역 머리글: 로고, 검색창, Pull requests/Issues/Marketplace/Explain 아이콘, 알림 종, + 새로 만들기, 아바타
2. 저장소 머리: 소유자/저장소 이름 경로, 공개 배지(Public), Pin/Unpin, 관심 표시 수(Star), 알림 받기(Watch) 드롭다운, 포크 수(Fork)
3. 탭 줄: Code, Issues(수), Pull requests(수), Agents, Actions, Projects, Wiki, Security and quality(수), Insights
4. 도구 줄: 브랜치 선택 드롭다운, "브랜치 n / 태그 n" 아님(GitHub는 브랜치 드롭다운 안에 Branches/Tags 탭이 있고 바깥에는 안 보임), Go to file(파일 찾기), Add file, Code(클론 드롭다운)
5. 마지막 커밋 막대: 작성자 아바타, 커밋 메시지(링크), 커밋 해시(짧게, 클립보드 복사), 상대 시간, History(커밋 수)
6. 파일 표: 이름(아이콘+링크), 마지막 커밋 메시지(말줄임), 마지막 업데이트(상대 시간)
7. README 영역: 파일 표 바로 아래, 제목 없이 바로 본문. 오른쪽 위에 연필(편집), Raw, 목차 아이콘
8. 오른쪽 사이드바(About): 설명 한 줄, 홈페이지 링크, Topics(칩), Readme 체크, Code of conduct 체크, License 체크, Security policy 체크, Activity(커밋 수, 브랜치 수, 패키지 수, 참여자 사진 n명+더보기, 릴리스 n개+최신 릴리스 이름과 날짜, 사용 언어 막대(색상+퍼센트))

## 3. 상태
- 로그인 전: + 새로 만들기, 알림 종 대신 "Sign in" "Sign up" 두 버튼. Watch/Star 버튼을 누르면 로그인 요구
- 로그인 후: 저장소라면 "Add file" 드롭다운 활성화(Create new file, Upload files)
- 빈 저장소: 파일 표 대신 "Quick setup" 안내(echo README, git init 명령 등). 우리는 R-28 업로드, R-27 새 파일로 대응하되 빈 상태 안내가 필요
- 큰 저장소: 파일 100개 넘으면 "항목이 많아 앞 N개만 표시" 같은 안내 없음(GitHub는 페이지네이션 없이 트리 전체를 가상 스크롤로 보여줌). 우리는 "항목이 많아 앞 30개만 마지막 변경을 표시합니다"를 쓰고 있는데, 이는 GitHub에 없는 문구이므로 06_밀도 기준대로 묶음 단위 지연 로딩으로 바꿔야 함(UX/07 8장)

## 4. 측정값(1440x900)
| 요소 | 값 |
|---|---|
| 탭 한 칸 높이 | 32px, 글자 14px/400 |
| 관심 표시 버튼 | 높이 28px, 글자 12px/500 |

## 5. 우리 화면(R-01) 대응과 차이
- 있음: 머리, 도구 줄, 커밋 막대, 파일 표, README, 오른쪽 정보 영역 — 구조 자체는 이미 대응됨
- 다름(우선순위 순)
  1. 파일 표 행 높이 51px(GitHub 40px), 이름 글자 17px(GitHub 14px) — 00_밀도_측정표 참고
  2. 사이드바 메뉴 버튼이 38px/17px/700으로 GitHub 전역 탭(32px/14px/400)보다 훨씬 큼
  3. 탭 줄 글자 굵기 700(GitHub 400) — 너무 두꺼워 보임
  4. "기관 확인 필요", "실행 환경 확인 필요" 같은 목록 반복 문구는 GitHub에 대응 요소 없음(UX/07 5장 위반)
  5. GitHub 브랜치 드롭다운 안에 Branches/Tags 탭이 있음. 우리는 바깥에 "브랜치 1개 태그 166개" 텍스트로 노출 — 유지해도 되나 드롭다운 안에도 탭 구조 추가 검토
  6. GitHub README에는 "제작자 설명에서 자동 정리했습니다" 같은 안내문이 없음. 원문만 보여줌(UX/07 "이 도구가 하는 일"→"소개" 교정과 일치)
  7. Fork 수가 About에 있는데 우리는 없음(추가 검토, 공공 맥락상 "포크"가 필요 없을 수도 있어 판단 필요)
