# 밀도와 문구 기준

- 문서 번호: UX-007
- 작성일: 2026. 10. 30.
- 상태: 확정(사용자 지시). 모든 화면, Figma와 코드에 적용
- 근거: 배포 화면 직접 확인(1440x900), GitHub와 공공 깃랩 직접 사용 기록(UX/handson)

## 0. 원칙: GitHub가 기본, 공무원용은 그 위에 덧붙인다
- 기본 화면은 GitHub다. 배치, 크기, 밀도, 메뉴 이름, 흐름이 GitHub와 같다. 공공 깃랩에만 있는 기능(그룹, 프로젝트 관리 묶음)은 공공 깃랩 방식으로 더한다
- 정부 정보 사이트처럼 보이면 실패다. 정부 사이트의 큰 제목, 안내 문장, 가운데 정렬 소개, 카드 격자, 단계별 마법사 화면, 큰 글자를 쓰지 않는다
- 공무원용 덧붙임(알파)은 GitHub 기본 구조를 바꾸지 않고 정해진 자리에만 들어간다
  | 덧붙임 | 들어가는 자리 | 모양 |
  |---|---|---|
  | 쉬운 풀이 | 용어 옆 또는 툴팁 | 보조 글자(3단계) 한 줄 |
  | 판단 정보(실행 환경, 기준 날짜, 이용 조건, 써 본 기관, 공개 준비 점검) | 오른쪽 정보 영역의 About 아래 | 라벨과 값 한 줄씩 |
  | 업무로 찾기 | 머리글 검색과 탐색 화면의 검색 | 같은 검색 입력, 문장으로 입력 가능 |
  | 써 봤어요 | 관심 표시 버튼 옆 | GitHub의 Watch, Fork 버튼 크기와 같은 버튼 |
  | 소개 카드, 분야, 실행 환경 판정 | 정보 영역과 목록 배지 | 자동 정리 표시와 근거 링크 |
  | 공개 준비 점검, 보안 파일 경고 | 설정과 업로드 흐름, 프로젝트 관리 묶음 | GitHub의 설정, 경고 표시 방식 |
  | 의견 양식, 요청 보드, 협업, 현황판, MCP, 인수인계, 개발 점검표 | 사이드바의 별도 묶음 "공무원 도구" | 다른 메뉴와 같은 모양 |
- 덧붙임이 코드 보기, 비교 화면, 파일 트리 안으로 들어가지 않는다
- 판정 기준: 덧붙임을 모두 가려도 GitHub 화면과 구분되지 않아야 한다

## 0. 기본값은 GitHub, 덧붙임은 자리를 더하는 것
- 기본 화면은 GitHub를 켰을 때와 구분되지 않아야 한다. 덧붙인 공무원용 요소(쉬운 설명, 판단 정보, AI 기능)를 가렸을 때 남는 화면이 순수한 GitHub/GitLab 화면과 같아야 통과다
- 금지: 정부 사이트식 구성. 큰 제목과 안내 문장으로 시작하는 머리말, 가운데 정렬된 소개 글, 같은 크기 카드 격자, 단계별 마법사(목적이 GitLab 원래 흐름과 다른 경우), 본문보다 큰 장식 글자
- 덧붙임은 아래 자리에만 둔다: 오른쪽 정보 영역 안, 목록 항목의 메타 줄 안, 탭 하나(예: 소개), 배지 하나. 새 레이아웃 블록을 만들지 않는다

## 1. 기본 화면 모드
- 기본은 어두운 화면이다. 처음 방문하면 어두운 화면으로 뜬다
- 이용자가 화면 설정에서 밝은 화면, 선명한 화면 모드, 시스템 설정 따르기를 고르면 그 값을 기억한다
- Figma는 어두운 화면을 대표 프레임으로 두고, 밝은 화면은 변수 모드로 같은 프레임에서 전환한다
- 개발 플랫폼 이용자(GitHub, GitLab 기본값은 시스템 설정이지만 개발자 화면은 어두운 화면 비중이 높다)와 코드 가독성을 근거로 한다

## 2. 삭제하는 것
- 맨 위 "이 누리집은 공공 저장소 개선 시제품입니다. 공식 전자정부 누리집이 아닙니다." 배너를 모든 화면에서 없앤다. 바닥글의 같은 취지 문구도 화면에서 뺀다
- 시제품 고지는 도움말의 "이 서비스에 대해"와 저장소 README에만 둔다
- 이용자에게 이용법을 설명하는 문장을 화면 머리에 두지 않는다. 예: "직접 만들기 전에 다른 기관의 도구부터 확인하세요. 로그인 없이 둘러볼 수 있습니다."
- GitHub, GitLab에 없는 큰 소개 문구(히어로)를 두지 않는다

## 3. 밀도 (GitHub 수준)
- 기준: GitHub 저장소 화면을 1440x900에서 열었을 때 보이는 정보량
- 목표: 1440x900 첫 화면에 도구 줄, 마지막 변경 막대, 파일 표 8줄 이상, 오른쪽 정보 영역 상단이 모두 보인다
- 글자 크기는 KRDS 글자 스타일 안에서 작은 단계를 쓴다. 본문 body/small, 보조 정보 body/xsmall, 제목은 한 단계 작게. 큰 단계(body/large, heading/xlarge)는 문서 읽기 화면에만 쓴다
- 표와 목록 한 줄 높이는 GitHub 값(약 40px)에 가장 가까운 KRDS 간격 값으로 정한다. 사이드바 항목은 약 32px
- 머리글 높이는 약 56~64px. 저장소 제목 크기는 heading/small 이하
- 구체 값은 GitHub 측정값(UX/handson/github)과 KRDS 변수를 대조해 결정 기록 D-14로 남긴다. Figma와 코드가 같은 값을 쓴다
- 목록 항목 사이 여백으로 밀도를 낮추지 않는다. 구분은 선 하나로 한다

## 4. 위계
KRDS 글자 스타일 세 단계로 구분한다.
| 단계 | 쓰임 | 스타일 |
|---|---|---|
| 1 | 화면 제목, 목록 항목 제목 | heading 또는 body 굵게, text/basic |
| 2 | 설명, 본문 | body, text/basic |
| 3 | 메타(기관, 날짜, 개수, 언어) | body/xsmall, text/subtle |

- 목록 항목은 제목 링크, 설명 한 줄 말줄임, 메타 한 줄 순서다
- 메타 한 줄은 아이콘과 간격으로 나눈다. 가운뎃점을 쓰지 않는다. 항목 예: 기관 이름(링크), 언어(색 점과 이름), 관심 수(아이콘과 숫자), 갱신(상대 시간 "3일 전")
- 날짜는 상대 시간(GitHub와 같다)이고, 마우스를 올리면 전체 날짜를 보여 준다. "2026. 10. 30. 갱신"처럼 길게 쓰지 않는다
- 실행 환경은 확인된 경우에만 KRDS 배지로 보여 준다. 모르는 값을 "확인 필요"로 목록마다 반복하지 않는다. 사용 방법과 정보 영역에서만 다룬다

## 5. 문구
공무원과 개발자가 같은 화면을 읽는다.
- 개발 용어는 GitLab, GitHub 한국어 원문 그대로 쓴다(커밋, 브랜치, 이슈, 머지 리퀘스트). 낯선 용어는 옆이나 툴팁에 짧은 풀이를 붙인다. 풀이는 보조 글자(3단계)로 쓴다
- 주어와 동사가 분명한 짧은 문장을 쓴다. 한 문장에 절은 둘 이하
- 금지: "~하는 것", "~을 얻는 것", "~할 수 있는 것", "~에 대한", 명사만 이어 붙이는 추상 표현, 기능 자랑, 느낌표, "~해 보세요"
- 금지 예와 고친 예
  | 금지 | 고침 |
  |---|---|
  | 이 도구가 하는 일 | 소개 (내용은 프로젝트 설명 원문 한국어 첫 문장) |
  | 실행 환경 확인 필요 | 실행 환경 미기재 (정보 영역에서만) |
  | 제작자 설명에 실행 조건이 없습니다. | 실행 환경 미기재 |
  | 아직 남겨진 기록이 없습니다. | 써 본 기관 0곳 |
  | 마지막 변경 내용 / 변경 날짜 | 최근 커밋 / 최근 업데이트 (공공 깃랩 원문) |
  | 더보기 > 공공 저장소 원본 화면에서 열기 | 공공 깃랩에서 열기 |
- 목록에 값이 없을 때 "기록 없음"을 쓰지 않는다. 비워 두거나 불러오는 중 표시를 쓴다
- 문구는 copy/ko.js 한 곳에서 관리하고 Figma와 같은 글자를 쓴다

## 6. 머리글 정렬
- 머리글 안쪽 좌우 끝이 본문 영역의 좌우 끝과 같다(같은 좌우 여백 변수)
- 오른쪽 묶음의 오른쪽 끝이 본문 오른쪽 끝과 일치한다. 로그인 전에는 "로그인"(보조 버튼)과 "계정 만들기"(주 버튼, 작은 크기)로 GitHub의 Sign in, Sign up 구성을 따른다

## 7. 로그인 화면
- 공공 깃랩 로그인 화면(UX/handson/gitlab/46_로그인화면.png)을 개선한다. 왼쪽 공지 영역, 오른쪽 입력 영역의 2열 구성을 유지한다
- 개선: 배경 그라데이션 제거(KRDS 면 색), KRDS 입력 부품과 위계, 공지는 제목과 본문 두 단계, 패스키 버튼과 등록 안내 정리, 어두운 화면 기본
- 좁은 폭에서는 공지가 입력 영역 위로 쌓인다

## 8. 파일 목록의 마지막 변경
- 모든 행에 최근 커밋과 업데이트를 보여 준다(GitLab 기본 동작). 앞 30개만 보여 주고 나머지에 "기록 없음"을 쓰지 않는다
- 방법: 보이는 행부터 묶음 단위로 불러오고, 불러오는 동안 빈 칸에 불러오는 중 표시

## 9. 더보기 메뉴
- KRDS 드롭다운 목록 부품을 쓴다. 항목은 한 줄 높이, 겹침 없음, 항목: 공공 깃랩에서 열기, 오류 신고

## 10. 구분선 글자와 페이지 제목
- 화면 글, 페이지 제목(브라우저 탭 글자), 메타 정보에서 세로선 글자 "|"와 가운뎃점을 구분 기호로 쓰지 않는다. "서울 학교 공간 지도 사용 방법 | 공공 저장소" 같은 제목을 쓰지 않는다
- 페이지 제목에 서비스 이름을 붙이지 않는다(GitHub는 "owner/repo: 설명"처럼 대상만 쓴다)
- 형식
  | 화면 | 제목 |
  |---|---|
  | 저장소 홈 | 만든사람/프로젝트: 프로젝트 설명 한 줄 |
  | 저장소 안 화면 | 화면 이름: 만든사람/프로젝트 (예: 이슈 #55: 만든사람/kordoc) |
  | 파일 보기 | 파일 경로: 만든사람/프로젝트 |
  | 전역 화면 | 화면 이름 (탐색, 검색 결과: 검색어, 알림, 로그인) |
- 목록과 정보 영역의 구분은 간격과 아이콘으로 한다. 프로젝트 설명 원문에 들어 있는 "|"(예: 한국어 | 영어 병기)는 한국어 부분만 쓴다
- 검사: 화면 문구 파일(ko.js), 컴포넌트 파일, Figma 글자에서 " | "와 가운뎃점을 찾아 0건(README 같은 사용자 원문 제외)


## 10. 세로선 구분 금지
- 글자 안에서 " | "(세로선)로 항목을 구분하지 않는다. AI가 흔히 쓰는 티가 난다
- 대신: 메타 줄은 간격과 아이콘으로 구분한다(이미 4장 규칙). 제목 줄은 ">" 경로 구분자나 줄바꿈을 쓴다
- 예외: KRDS 부품 내부 원문, 프로젝트 설명이나 README 원문(제작자가 쓴 원문은 고치지 않는다)
- 검사: 화면 글자에서 " | " 포함 개수를 세고 0으로 만든다(예외 제외)

## 11. 간결 표기 (2026. 10. 30. 사용자 지적: "와, 과를 굳이 오래 많이 쓰냐, 간결해야지")
- 이름, 제목, 메뉴, 탭, 분류, 라벨은 명사 나열이다. 와, 과, 및, 그리고로 잇지 않는다. 둘을 묶어야 하면 빗금(/)으로 쓴다. 가운뎃점은 쓰지 않는다
  | 전 | 후 |
  |---|---|
  | 문서와 자료 | 문서/자료 |
  | 출장과 회계 | 출장/회계 |
  | 민원과 복지 | 민원/복지 |
  | 인사와 교육 | 인사/교육 |
  | 시설과 안전 | 시설/안전 |
  | 데이터와 정보화 | 데이터/정보화 |
  | 브랜치와 태그 | 브랜치/태그 |
  | 법령과 기준 변경 알림 | 법령/기준 변경 알림 |
  | 협업과 팀원 모집 | 협업/팀원 모집 |
  | 작업과 결과물 | 작업/결과물 |
  | 작성과 미리보기 | 작성/미리보기 |
- 한 이름은 1~3어절이다. 4어절 이상이면 줄인다
- 목록 안에서 단위 앞의 반복 낱말을 뺀다: "도구 153개"는 "153". 단위가 필요하면 한 번만(제목 줄에 "도구 464")
- 문장형 설명(~입니다, ~합니다, ~하세요, ~없습니다)은 쓰지 않는다. 필요한 설명은 명사구로 줄이거나 툴팁으로 옮긴다
  | 전 | 후 |
  |---|---|
  | 분류 중복 가능. 실제 수요나 미개발 분야를 확정하지 않습니다. | (삭제, 필요하면 "분류 기준" 링크 하나) |
  | 개인정보와 비밀번호, 인증 키가 든 파일은 올리지 않습니다. | 개인정보/인증 키 파일 제외 |
  | 사용 방법과 실행 환경 설명을 요청합니다 | 사용 방법/실행 환경 요청 |
- 단계: 이름 줄이기, 같은 뜻의 문장 삭제, 남은 설명은 보조 글자(13) 한 줄
- 검사: copy/ko.js와 화면 글자에서 "와 ", "과 ", "및", "입니다", "합니다", "하세요", "않습니다"를 찾아 목록을 만들고 하나씩 처리한다. 사용자 원문(README, 프로젝트 설명)은 제외
- 카테고리 이름은 server/src/analysis.js의 분류 값에서도 같은 형태로 바꾼다(화면과 데이터가 어긋나지 않게)

## 12. 외부 링크 아이콘 금지와 메뉴 규칙 (2026. 10. 30. 사용자 지적)
- 외부 링크 옆에 오른쪽 위로 향하는 화살표 아이콘(↗, 외부 링크 사각 화살표 아이콘 포함)을 쓰지 않는다. 'KRDS 출처', '새 창에서 열기' 같은 링크는 글자만 쓴다. 새 창으로 열리는 링크는 aria-label에 '새 창'을 붙이고 target=_blank rel="noopener noreferrer"를 쓴다
- 글자 사이에 장식용 화살표(→, ↗, ›)를 쓰지 않는다. 쓸 수 있는 방향 표시는 KRDS 부품 고유 아이콘뿐이다(드롭다운 아래 꺾쇠, 이동 경로 구분자, 아코디언 꺾쇠)
- 메뉴(더보기, 드롭다운, 팝오버, 컨텍스트 메뉴)
  - 항목은 한 줄이다. white-space nowrap, 폭은 가장 긴 항목 + 좌우 padding 12(최소 160, 최대 320)
  - 항목 높이 32, 항목 사이 간격 0, 항목 안 padding 8 12, 글자 15 보통, 호버는 회색 면
  - 위치는 버튼 아래 왼쪽 또는 오른쪽 끝 정렬로 화면 밖으로 나가지 않게(뷰포트 가장자리 12 여백)
  - 항목이 글자 조각으로 갈라지거나(예 '공공 / 깃랩에서 / 열기') 겹치면 위반
  - 항목 글자는 동사형이 아니라 명사 나열 11장을 따른다: '공공 깃랩에서 열기', '오류 신고'
- 구현: 모든 메뉴는 `app/src/components/Navigation/Menu.jsx` 한 부품이다(더보기, 탭 줄 더보기 묶음, 코드, 파일 추가, 브랜치 선택, 정렬, 화면 설정, 계정, 사이드바 접힘 묶음, 내려받기). 값은 layout.tokens.css의 --rb-menu-* 변수. 항목 세로 padding은 0이고 높이 32를 고정한다(글자 15 줄 높이 22에 padding 8을 더하면 38이라 32가 안 된다)
- 새 창 링크는 `newWindow(글자)`(components/Layout/newWindow.js)만 쓴다. target=_blank를 직접 쓰면 audit:code가 실패한다
- 브랜드: 서비스 이름은 '공공 깃랩'. 머리글은 로고(높이 24) + 이름(15 굵게)이 한 링크(접근성 이름 '공공 깃랩 홈'), 바닥글은 로고 높이 20. 로고 도형은 app/public/brand/gitlab-logo.svg, 색은 로고 고유색(팔레트 규칙의 예외)
- 검사: 코드는 모든 메뉴를 열어 항목 높이, 줄 수, 폭을 스크립트로 측정(항목 줄 수 1, 높이 32), audit:code에 외부 링크 아이콘 금지 검사 추가. Figma는 메뉴 부품(menu, dropdown, popover) 전 변형의 글자 줄 수 1과 너비 HUG를 점검
