## 4. 부품 인스턴스 안 표시 조정

- 헤더의 사용하지 않는 유틸리티 메뉴와 슬로건 자리, 메인 메뉴 펼침 영역은 숨겼다. 항목 이름만 실제 메뉴로 바꿨다.
- 푸터의 연락처 예시, 관련 사이트 자리, 인증마크 이미지 자리표시는 숨겼다. 허위 연락처나 인증마크를 표시하지 않는다. 정책 링크와 출처, 정부 로고 자리는 유지했다.
- 구조화 목록의 체크박스, 태그, 기간, 신청 버튼처럼 이번 과업에 필요 없는 선택 요소는 숨겼다. 제목, 하는 일, 기관과 실행 형태만 남겼다. 장식용 외곽선은 제거했다.
- 모바일 탭은 KRDS `tab__atomic__mo`를 사용하고 폭을 `size-height/9`(64)에 연결했다. 내용은 두 줄을 허용하고 세로는 Hug로 늘린다. 328 안쪽 폭에 5개 탭과 `gap/1` 네 개가 정확히 들어가도록 했다.
- PC 탭은 콘텐츠 1200 폭에서 gap0, Fill 다섯 개로 240씩 나뉜다. 소수 폭을 없앴다.
- 모두 인스턴스를 유지했다. detach하거나 별도 가짜 부품을 만들지 않았다.

## 5. 최종 규칙 검사와 파일

- 총 28프레임: 기존24 + P-07 Empty4. PC1920, 모바일360, light와dark.
- `audit_figma.py` 28프레임 모두 위반0. KRDS 밖 부품0. 소수 크기0.
- 검사 입력은 Figma 편집기에서 읽은 현재 노드의 실제 값과 실제 mainComponent key를 REST 형태로 내보낸 자료다. 기본 검사 기준대로 KRDS 인스턴스 내부는 KRDS 책임 영역으로 건너뛴다.
- 검사 JSON과 보고서: `figma_png/audits/`. PNG 28개 덮어쓰기 완료: `figma_png/`.
- 노드 목록: `figma_png/nodes.json`.
- 다크 변수 모드와 반응형 변수 모드는 각 최상위 프레임에 명시했다.
- 규칙 감사 통과는 전체 접근성이나 사용자 과업 성공 검증 완료를 뜻하지 않는다. 실제 키보드, 스크린리더, 다운로드, 로그인 및 좁은 화면 동작은 코드 단계에서 검증한다.

### 추가 가독성 보정
- 목록의 숨긴 신청 버튼을 담던 일반 프레임도 함께 숨겼다. 버튼만 숨기면 48 높이와 앞 간격이 남아 빈 공간이 생기는 것이 원인이었다.
- 목록 제목은 Hug 높이와 Fill 폭으로 긴 제목을 줄바꿈한다. 고정 높이 때문에 긴 이름이 잘리는 것을 방지한다.
- 검색 자리표시는 비활성 글자가 아니라 입력을 안내하는 글자다. 공식 text_input의 자리표시 색을 `color/text/subtle`로 연결했다. 어두운 면 #33363D에서 #CDD1D5 대비는 7.88:1이다. 실제 비활성 상태의 의미와 혼동하지 않게 한다.

### 자료와 상태
- 파일명·README는 기존에 직접 조회한 1069 원문(UX/sources/)을 사용했다. 기관·프로젝트 이름도 앞선 실제 자료만 사용했다.
- P-09 Passed/Blocked는 실제 점검 결과가 아닌 설계 상태이며 프레임 밖 주석에 표시했다. 화면 문구는 '자동 점검 항목 모두 통과', '자동 점검 항목의 통과는 공개 승인이 아닙니다.'로 구분했다. 서버 canPublish:false를 공개 승인으로 오해하지 않게 한다.
- 서버 checks gitignore/readme/purpose/usage/environment/license/tests/ci와 owner-only, 부분 점검 한계를 화면에 반영했다.
- 의견·요청·변경 기록은 실제 기록을 만들지 않고 Empty를 기본으로 설계했다.
