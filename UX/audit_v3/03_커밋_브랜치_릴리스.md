점검일 2026-10-31. 실제 https://gitlab.aigov.go.kr (로그아웃, 읽기만, 요청 간격 1.1초 이상), 우리 https://hyunho2378.github.io/public-repo-krds/ . 코드, Figma, push 변경 없음.

## 범위와 한계 (먼저 읽을 것)
- 대상 프로젝트: id 150 kordoc 하나만 점검했다. 두 번째로 id 149 korean-law-mcp(릴리스 1개 확인)를 골랐으나 시간 때문에 화면 대조는 하지 못했다. 미점검.
- 스크린샷: 150 기준 6화면 x 3폭(1280, 1440, 1920) x 실제/우리 = 36장과 나란히 비교 18장을 shots/에 저장했다. 비교 이미지는 1440, 1280, 1920 모두 만들었고 직접 열어 본 것은 1440 6장이다. 1280, 1920은 저장만 했고 육안 확인 전이다.
- 계산값(computed style) 측정: 1440 폭에서만 했다. 커밋 행, 브랜치, 태그, 릴리스, 비교의 주요 요소만이다. 커밋 상세는 스크린샷 육안 대조만 했고 계산값 표는 없다.
- 인터랙션: 우리 커밋 행 펼침과 포커스 링만 측정했다. 실제 쪽 펼침은 셀렉터가 맞지 않아 측정 실패(행 높이 58 그대로, aria-expanded false). 날짜 묶음 접기, 키보드 이동, 메뉴 열고 닫기, 로딩 표시, 줄 펼치기, 리비전 비교 결과 화면은 미점검.
- 사이드바는 측정하지 않았다. 경계 위치만 기록: 1440에서 실제 본문 시작 x=433(사이드바 오른쪽), 우리 x=448(h1) 또는 448(탭). 우리가 15px 더 오른쪽이다.
- 실제 쪽에서 커밋 행 폭/좌표를 한 번 재창 직후에 읽어 x=95로 나온 값은 버린다(레이아웃 전환 중). 아래 행 치수는 높이, 글자, 색, 패딩만 쓴다.
- 스크린샷 안 거리 환산: 비교 이미지는 표시 폭 2000 기준이며 CSS px = 표시 px x 1.445 (비교 이미지) 또는 x 0.72 (단독 이미지 1440 폭).

## 우선순위 P0 요약 (사용자가 바로 이상하다고 느낌)
1. 커밋, 태그, 릴리스, 비교 모든 화면의 h1이 실제 30px인데 우리는 19px (항목 1, 26, 30). KRDS 글자 크기에서 24px가 상한이므로 24px로 맞추는 선택지가 규칙 안.
2. 커밋 목록의 날짜 묶음에 세로 타임라인 선과 행 들여쓰기가 없음 (항목 2).
3. 커밋 상세 정보 상자가 4줄에서 1줄로 줄어 브랜치, 관련 태그, 관련 머지 리퀘스트 줄이 없음 (항목 13).
4. 커밋 상세의 변경 비교 기본값이 실제는 나란히, 우리는 인라인이며 컨트롤 모양도 다름 (항목 14).

P0 기준을 엄격히 잡아 4건뿐이다. 나머지는 P1(필터 줄 높이, 아바타 모양, 탭 개수 표시, 배지와 버튼 채움, 비교 화면 구성 등)이다.
