## 3. 과제별 단계 수 (1280x900)

클릭은 마우스 클릭, 입력은 키 입력, 전체 로딩은 문서를 통째로 새로 불러온 횟수다.

| 과제 | 실제 | 우리 | 차이 |
|---|---|---|---|
| 1 kordoc 찾아 README 열기 | 클릭 3(필터 칸, 프로젝트, README.md) + 입력 6 + Enter 1. 프로젝트 이동은 전체 로딩 1회, README는 로딩 없이 전환, URL에 ?ref_type=heads 붙음 | 클릭 3(필터 칸, 프로젝트, README.md) + 입력 6, Enter 불필요. 로딩 없음. 프로젝트 이동 후 제목과 첫 행이 670ms 비어 있음 | 단계 수는 같고 Enter 한 번이 덜 든다. 빈 화면 670ms가 우리 쪽 문제 |
| 2 최근 커밋 보기 | 클릭 1(N 커밋 링크). 전체 로딩 1회 | 클릭 1. 로딩 없음, 26ms 만에 전환 | 같음 |
| 3 브랜치에서 main 찾기 | 클릭 1(사이드바 브랜치). 전체 로딩 1회. main 표시됨 | 클릭 1. 로딩 없음, 첫 프레임 16ms에 제목이 비고 31ms에 채워짐. main 표시됨 | 같음 |
| 4 검색 상자로 hwp 검색 | 클릭 1(검색 버튼, 모달이 열림) + 입력 3 + Enter 1. 전체 로딩 1회. 결과 URL /search?search=hwp&nav_source=navbar | 클릭 1(검색 칸) + 입력 3 + Enter 1. 로딩 없음. 결과 URL /search?q=hwp | 같음. 첫 프레임에 이전 화면 문구가 남음 |
| 5 뒤로 가기로 목록 위치 복원 | 스크롤 1109, 상세 이동 후 뒤로 가면 1109 즉시 복원 | 스크롤 1100, 뒤로 가면 맨 위에서 시작해 750ms 동안 1100까지 내려옴 | 우리 튕김 있음 |
| 6 새로고침 후 같은 화면 | 같은 URL, 같은 화면, 스크롤 0으로 시작 | 같은 URL(/projects/150/changes), 같은 화면, 스크롤 0으로 시작 | 같음 |

## 4. 키보드와 포커스 (탐색 화면, Tab 20번)

- 실제: 건너뛰기 링크, 홈, 탐색, 검색 단추, 등록, 로그인, 사이드바 8개와 도움말, 사이드바 접음, 빵 부스러기 2개, 활성 탭 등 문서 순서대로 진행. 포커스 링은 상자 그림자
- 우리: 활성, 비활성, 최근 검색, 필터 입력, 검색, 업무 분야, 정렬 2개, 첫 프로젝트와 아이콘 링크로 이어짐. 상단 바와 사이드바는 거치지 않음(문제 20)
- 과제 1~4를 키보드만으로 하는 실험은 하지 않았다. 따라서 "키보드로 수행 가능"은 확인하지 않았다

## 5. 요약

P0는 7개다(문제 1, 2, 3, 4, 17, 18, 20). 10개를 채우려고 늘리지 않았다. 필터 막대 줄바꿈, 파일 표 열 줄어드는 순서, KRDS 칼럼, 대비, 키보드만으로 과제 수행은 측정하지 못해 판정에서 뺐다.
