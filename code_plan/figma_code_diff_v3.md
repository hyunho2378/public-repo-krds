### 2-1. 사용 방법 단계 출처 확인(부모 요청)
- 명령은 README에 적힌 것만 쓴다. 새로 만들지 않는다. kordoc 기준 결과:
  - 1. 코드 내려받기 → 저장소 주소(API의 `http_url_to_repo`)
  - 2. 설치 → `npm install kordoc` (README 31행)
  - 3. 실행하기 → `npx -y kordoc setup` (README 39행)
  - 4. 실행하기 → `/plugin marketplace add chrisryugj/kordoc` (README 51행)
  - 5. 실행하기 → `/plugin install kordoc@kordoc` (README 52행)
  - 6. CLI → `npx kordoc 문서.hwpx -o 문서.md` (README 62행)
- 뽑는 규칙: 코드 블록 안의 줄만, 주석과 빈 줄 제외, 같은 명령은 한 번만, 최대 6개. 줄 번호는 README 원문 기준이다(`components/Help/Readme.jsx`의 `readmeCommands`).

## 4. 남은 차이의 성격
- 수치가 2.9~8.2%로 남는 가장 큰 까닭은 글자 크기와 줄 높이, 칸 사이 간격이다. Figma는 디자인 값, 코드는 KRDS 공식 CSS 계산값을 쓴다.
- 받아 둔 자료의 한계(목록 100개)로 생기는 숫자 차이는 디자인 차이가 아니다.
- 색은 둘 다 KRDS 변수를 쓰므로 계산값으로 따로 확인한다. 브라우저 캡처 색 보정 때문에 그림 비교로는 색을 판정하지 않는다.

### 판단이 필요했던 두 가지 (공공 깃랩 실제 동작과 서버 결과로 정함)

1. **파일 정렬**: 공공 깃랩 API가 주는 순서가 `.Codex, .claude-plugin, .claude, .github, THIRD_PARTY, bench ...`다. 폴더 먼저, 이름은 대문자가 앞선다. 코드가 `localeCompare`로 다시 정렬해 `.claude`가 앞에 오던 것을 고쳤다. 이제 받은 순서를 그대로 쓴다. Figma와 같다.
2. **"이 도구가 하는 일" 문장**: 서버 소개 카드(`/api/v1/projects/150/card`)의 `summary`가 kordoc에서는 `null`이다. 그래서 코드는 프로젝트 설명을 정리해 쓴다. Figma의 문장("HWP, HWPX, PDF, Office 문서를 Markdown으로 바꾸고 ...")은 서버가 만들어 내는 값이 아니다. Figma 갈래에 알렸다.

### 남은 차이
- R-01 1920 Guest 6.39%, Signed-in 6.97%. 남은 것은 글자 렌더와 아주 작은 간격이다.
- 커밋 막대 아바타: Figma는 사진, 코드는 머리글자다. 공개 아바타 주소(`avatar_url`)를 쓸지 정해야 한다.
- 코드 버튼: Figma는 글자만, 코드는 펼침 화살표가 붙는다(KRDS 드롭다운 기본).
