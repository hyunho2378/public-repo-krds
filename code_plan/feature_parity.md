# 기능 전수 점검표 (공공 깃랩 + GitHub)

- 기준: PRD-001 0장 제품 정의. 기본 사이트는 공공 깃랩과 GitHub의 모든 페이지와 기능을 그대로 가진다. 디자인 시스템만 KRDS다.
- 근거 화면: `UX/handson/gitlab/`, `UX/handson/github/`, `artifacts/UI역설계/`
- 번호 체계: `UX/05_화면_전수목록.md`의 R(저장소), G(전역), A(더하는 기능)를 따른다
- 상태: 완료(화면과 실제 자료), 읽기만(로그인 필요한 자료는 안내), 미착수
- 방식 칸: "원래 그대로"는 공공 깃랩과 GitHub의 메뉴, 버튼, 문구, 흐름을 그대로 옮긴 것이다. "개선"은 그 위에 더한 것이며 이유를 적는다. 원래 기능을 빼거나 숨기지 않는다
- 공개 API 확인(2026. 10. 30., 비로그인): events, wikis, pipelines, packages, compare, releases, tree, commits, branches, tags, contributors, issues, merge_requests는 200. labels, milestones, members, boards, snippets는 401이라 로그인 안내를 보여 준다.

## 5. 공무원과 개발자를 함께 만족시키는 규칙 (UX-001 2.3, 2.4)

- 원래 기능을 숨기거나 접지 않는다. 원래 이름을 그대로 쓰고 옆에 쉬운 설명을 덧붙인다. 보기: 왼쪽 메뉴 "브랜치와 태그 / 작업 갈래", "변경 제안 / 코드 반영 요청", "릴리스 / 배포 버전"
- 쉬운 설명은 코드, 변경 비교, 파일 목록 영역 밖에만 둔다
- 단축키는 GitLab, GitHub와 같게 한다. `/` 검색, `t` 파일 찾기, `f` 파일 트리 검색
- 코드 보기는 고정폭 글꼴, 줄 번호, 일정한 줄 높이, D-05 구문 강조를 쓴다
